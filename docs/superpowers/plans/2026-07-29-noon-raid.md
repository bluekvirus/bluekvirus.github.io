```js
// Pure: no three.js types in or out — Node-testable.
// points: [[x,y,z], ...]; returns { distance, center: [x,y,z], lookAt: [x,y,z] }
export function fitCamera(points, aspect, { fov, margin, lookLift, viewDir }) { /* ... */ }
```

Math: bounding sphere from the point set (centroid + max radius is acceptable); `vHalf = fov/2` in radians; `hHalf = atan(tan(vHalf) * aspect)`; `distance = R / sin(min(vHalf, hHalf)) * margin`; camera position = `center + normalize(viewDir) * distance`; `lookAt = center + [0, R*lookLift, 0]`.

Wire: call on mount and in `onResize`; `state.camBase` set from the result; camera fov fixed at `FOCUS.fov`; drift/parallax amplitudes scale by `R/1000`. Keep `state.small` mount-time (documented). Remove the old `LAYOUT.camFrame` lerp constants and `camBase`/`camTarget` if no longer referenced (update any test that asserts them).

- [ ] **Step 1: Write the failing test** `tests/framing.test.mjs` — import `fitCamera` from a pure module (put the function in a new `themes/dune/framing.js` with NO three import so Node can load it; `main.js` imports it):

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { fitCamera } from '../themes/dune/framing.js';

const OPTS = { fov: 52, margin: 1.12, lookLift: 0.1, viewDir: [0.42, 0.3, 0.86] };
const BOX = [[-50, 0, -300], [50, 0, -300], [-50, 0, -200], [50, 0, -200], [0, 30, -250]];

test('narrower aspect pushes the camera farther back', () => {
  const wide = fitCamera(BOX, 21 / 9, OPTS);
  const square = fitCamera(BOX, 1, OPTS);
  const tall = fitCamera(BOX, 9 / 19.5, OPTS);
  assert.ok(square.distance > wide.distance);
  assert.ok(tall.distance > square.distance);
});

test('wide aspects clamp to the vertical fit (distance stops shrinking)', () => {
  const a = fitCamera(BOX, 16 / 9, OPTS).distance;
  const b = fitCamera(BOX, 32 / 9, OPTS).distance;
  assert.equal(a.toFixed(4), b.toFixed(4));
});

test('subject projects to a similar frame fraction across aspects', () => {
  const vHalf = (52 / 2) * Math.PI / 180;
  for (const aspect of [21 / 9, 16 / 9, 4 / 3, 1, 3 / 4, 9 / 16]) {
    const { distance, center } = fitCamera(BOX, aspect, OPTS);
    const R = Math.max(...BOX.map(p => Math.hypot(p[0] - center[0], p[1] - center[1], p[2] - center[2])));
    const hHalf = Math.atan(Math.tan(vHalf) * aspect);
    const half = Math.min(vHalf, hHalf);
    const fraction = Math.asin(R / distance) / half; // 1.0 == exactly fills the tighter axis
    assert.ok(fraction > 0.8 && fraction <= 1.0, `aspect ${aspect} → ${fraction}`);
  }
});

test('camera sits along viewDir at the fitted distance and looks slightly above center', () => {
  const { distance, center, lookAt } = fitCamera(BOX, 16 / 9, OPTS);
  const len = Math.hypot(...OPTS.viewDir);
  const pos = OPTS.viewDir.map((v, i) => center[i] + (v / len) * distance);
  assert.ok(Math.abs(Math.hypot(pos[0] - center[0], pos[1] - center[1], pos[2] - center[2]) - distance) < 1e-6);
  assert.ok(lookAt[1] > center[1]);
});
```

### Task 5: Living attrition — engage, die, reinforce

**Files:** Modify `themes/dune/troops.js` (owns all state), `themes/dune/combatfx.js` (reports impacts, skips dead shooters), `main.js` (wiring only if needed), `layout.js` (reinforcement entry points).

**Contract changes (both consumers must agree):**
- Each `units[i]` gains `alive: boolean` and `state: 'advance'|'cover'|'fire'|'dying'|'down'|'reinforce'`. `firing` stays and must be false unless `state === 'fire'` and `alive`.
- `createTroops()` additionally returns `reportImpact(unitIndex, elapsed)` — called by `combatfx` when a tracer lands on that unit. Troops owns the kill roll and all resulting state.
- `combatfx` must skip firing for `!alive` units and must not target `!alive` units.

**Build requirements:**
- **Seeded PRNG stream** (e.g. mulberry32 seeded from a constant) advanced ONLY inside `reportImpact` and reinforcement scheduling — never per frame, never `Math.random()`. Under reduced motion (`dt === 0`) no impacts are reported (FX doesn't spawn), so the stream never advances and the frozen frame is stable.
- **Kill chance ~22% per impact.** On kill: `dying` for ~0.8s (fall: pitch to prone with slight yaw scatter, drop to `duneHeight`), then `down` for ~20s (a prone body on the sand, still rendered by the same InstancedMesh — no new meshes), then a ~3s sink/fade, then recycled.
- **Reinforcements:** recycled units re-enter as `reinforce` from faction entry points in `layout.js` (Fremen from the eastern dunes, Harkonnen from behind the harvester), advancing to an open post before resuming normal behavior. Stagger arrivals so the line visibly thins and refills; live counts stay within ±3 of nominal 10 Fremen / 8 Harkonnen.
- Both factions take losses; neither is ever wiped out.
- No new draw calls (bodies reuse the faction InstancedMeshes); zero per-frame allocations; existing waypoint de-confliction must keep holding for live units (prone bodies may be closer together — that's fine and realistic, but a body must not sit inside a live unit).

- [ ] **Step 1:** Implement troops state machine + PRNG + reinforcement scheduling.
- [ ] **Step 2:** Implement `combatfx` impact reporting + dead-unit skipping.
- [ ] **Step 3:** Verify behaviorally via the debug handle over a simulated 120s (step `update` in a loop): deaths occur, bodies appear and clear, reinforcements arrive, live counts stay within ±3 of nominal for both factions, no unit ever overlaps another live unit by <3 units, and the PRNG is never advanced when `dt === 0`.
- [ ] **Step 4:** Visual iteration (≤5 rounds) over ≥60s of real playback. **Criteria:** (a) soldiers visibly fall when hit — the fall reads as a death, not a glitch; (b) bodies accumulate briefly on the sand then disappear plausibly; (c) reinforcements are visible walking in, not popping into existence; (d) the battle line persists and feels ongoing over a minute of watching; (e) reduced-motion frame is still, includes a body or two, and never changes.
